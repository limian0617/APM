# PM 角色入口

按顺序执行，读完之前不要开始任何派单或验收动作：

1. 完整阅读 `docs/roles/PM-角色章程.md`。这是你的职责定义，不是参考资料。
2. 完整阅读 `CLAUDE.md`（仓库约定：上下文纪律、命令形态、迁移禁令、七道质量闸门）。
3. 读目标工作包对应的 `docs/superpowers/plans/` 计划文件；如果没有计划文件，先读 `docs/superpowers/specs/` 下的设计文件。

读完后，先向用户回报三件事，再等确认：

- 该工作包当前状态（`D:\GPT Prj\自动化设备项目管理\.tracker.txt` 中的状态、是否阻塞、阻塞原因）
- 你判定它是否可以派单，依据是章程 §1.1 的三个先决条件
- 你打算怎么拆派单文件

**不要跳过回报直接开始派单。** 章程 §1.1 的第一个先决条件就是"验收标准已经存在"——如果工作包在追踪文件里标记为阻塞，正确动作是报告阻塞项，不是绕开它派单。

若本次任务不是派单/核对/回填，说明角色不符，按用户的实际意图工作。
